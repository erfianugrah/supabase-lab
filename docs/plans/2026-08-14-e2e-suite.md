> **STATUS 2026-08-14: IN PROGRESS.** The operator installed
> @playwright/test, wrote playwright.config.ts and the landing probe, and the
> wiring it tests is already live: edge-cached read path, graph viz, as-at

**Goal:** four spec files under `demo/e2e/` that run green against
`https://pggraph.erfi.dev` with `bunx playwright test`, serially.

## The flows to prove

Selectors come from `demo/src/components/Explorer.tsx` - READ IT before
writing each spec. Use role/text selectors; no screenshots, no visual diffs.

1. `bridging.spec.ts`
   - Cross-document entities table lists person rows (a PERSON badge is
     visible in the first data row - the top bridge is a councillor).
   - The per-row <details> expander labelled "N documents" opens and shows
     doc slugs (details/summary is native; click the summary, assert the
     details[open] content contains "inv-minutes-").
   - As-at: fill the date input (label "as at") with 2020-01-01. Only one
     corpus document predates that, so no entity can bridge -> the table shows
     zero data rows. Clear the input and rows return. That is the temporal
     query proven from a browser.
2. `entity.spec.ts`
   - Entity search for "Wendy Wilks", OPEN the first result:
     the Selected entity panel shows the name, the Graph section renders an
     svg with more than 10 circle nodes, the Neighbourhood table has rows,
     and the Timeline table's first date cell matches /\d{4}-\d{2}-\d{2}/.
   - Persistence: the URL now contains `?entity=`, reload the page, assert
     the same selected-entity heading is back without any interaction.
   - Shortest path: SET TARGET on the first neighbourhood row, FIND PATH,
     assert the path table (or the NO PATH diagnostic) renders.
3. `search.spec.ts`
   - Entity search "White Rock Wind Farm", OPEN the org row, and the
     Registry identifiers section shows `45 153 592 173`. That is the
     checksum-pinned closed loop, proven end to end.
   - Document search for "White Rock": the results table lists rows whose
     snippet text mentions white rock (case-insensitive).
4. `offline.spec.ts`
   - `page.route("**/rest/**", route => route.abort())` before goto:
     the page shows the DIAGNOSTIC: DATA SOURCE UNAVAILABLE panel. This is
     the only spec that stubs anything - and it proves the failure UX.

## Constraints

- Read-only: every RPC the UI calls is a read; the suite must not POST
  anything the UI itself would not.
- Exact corpus facts only where they track the committed corpus
  (111 documents, the ABN above). Entity ids are NOT stable across re-seeds:
  never hardcode one (the id 11309 exists today only in this live project).
- Serial (workers: 1 is set in the config; do not change it).
- If a flow depends on a panel being visible, assert visibility before
  interacting; no fixed sleeps.

## Out of scope

New UI work. If a spec cannot pass because the UI is wrong, STOP and report;
do not edit components (they are outside the fence on purpose).
